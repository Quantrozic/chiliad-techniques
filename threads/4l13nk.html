Neutral Weather is Only Called in North Yankton

▲ 38 ptsu/Caffine1May 25, 201614 comments at captureOpen original on Reddit ↗
Documented under:Procedural Weather-Cycle Triggering ?Procedural Weather-State Sweep ?

I mentioned this in a comment earlier this week, but there are so many question about neutral weather I wanted to ensure everybody saw.

So far, the only known instance of neutral weather being set ingame is at line 57796 of prologue1.c4

                        GAMEPLAY::SET_WEATHER_TYPE_NOW_PERSIST("NEUTRAL");

It's part of a larger sub:

            if (!sub_78e39(278)) {
                if ((CUTSCENE::GET_CUTSCENE_TIME() > SYSTEM::ROUND(38.053 * 1000.0)) && CUTSCENE::_708BDD8CD795B043()) {
                    sub_78e28(278, 1);
                    GRAPHICS::CLEAR_TIMECYCLE_MODIFIER();
                    if (GRAPHICS::GET_TIMECYCLE_MODIFIER_INDEX() != -1) {
                        GRAPHICS::_1CBA05AE7BD7EE05(0.0);
                    }
                    GAMEPLAY::SET_WEATHER_TYPE_NOW_PERSIST("NEUTRAL");
                    GAMEPLAY::_SET_CLOUD_HAT_TRANSITION("RAIN", 0);
                    for (v_2 = 0; v_2 < l_41B; v_2 += 1) {
                        sub_54c70(&l_41B[v_2/*1*/]);
                    }
                }
           }

What does this mean? Well from what we know, the only time in the code that this weather is set is in that one moment during the prologue in connection with a cutscene.

It's possible that there's obfuscated code that sets it at some other time, but of all the known code, this is the only time it's set. In addition, it's obviously not part of the regular weather cycles.

Here's the files that define what neutral weather does.

  • \common.rpf\data\timecycle\w_neutral.xml
  • \update\update.rpf\common\data\timecycle\w_neutral.xml

If anything changes, I'll be sure to update.
