Brute Force Tactics - Vol 1 - The Hippy Camp

Documented under:Base-N Encoding Brute SweepVigenère Cipher Brute-Force Testing

Hello! This is your friendly neighborhood MythBuster here. I decided that in light of the fantastic Grid Search Tadden started, we should also try another type of searching based on the idea of Brute Forcing.

Lets start be defining our goals:

Brute Force Testing means trying all possible things for a result. This means we will be trying a multitude of different methods based on ideas or instincts in an attempt to make something happen at an area in the game. When/If we get a result by doing things, we will need to keep track of what was done and try to replicate the exact conditions.

Setting up your conditions is vital - Start by setting up the save for testing that you would like to try. Based on previous experience, the game loads different things for different reasons - Area of effect, time, location, special event call, seeing a specific thing, weather ect. This means that we will need to have those things logged proper. The day, time, weather, and moon phases should be noted at the beginning of the save. This ensures that whatever someone gets to happen will be able to be replicated across all games, and that we can narrow down variables. Please note that you should have a valid 100% save to start this so the UFO's will be active. Please set the starting save point somewhere OUTSIDE the area being looked at as reloading the area several times is a valid testing method - The game holds onto areas you have loaded, so when you need a fresh load, leave far enough that the game would unload the area. You can test this by looking at specific NPC's (make sure not to disturb them so they run off/fight you!) and seeing if the exact same ones are still in those spots. (the game pulls NPC's from a pool of possible setups, meaning if an area was unloaded/reloaded, their should be a different configuration of NPC in a spot. Remember something specific about them and leave/come back to see if new NPC's spawned.)

Actually testing things should have a method - Come up with something that you want to test and attempt to test it over a few in-game days.(This is to ensure that things like 3am and multiple weather changes happen, in case these things are parts of other triggers.) Make sure to take screenshots/video of any weirdness so we can try to replicate it. Basically, pick something you think might happen and test it by doing that thing under conditions by loading the save up fresh and testing it. This could mean using the area in question as a start/end point for other tests (a trail between areas, perhaps) or testing with a multi-person hangout... I will not tell you what to test, but come up with something you can prove/disprove as far as in-game ideas and try for it. Nothing is off limits as long as you document anything odd.

Reporting back with anything to tell* - Write a comment below including the character used, time, day and weather of your save, anything you tried to do, link's to the videos of your testing, and any results you have to share. If something strange or weird should occur, the first thing to do is to load up your save and see if you can make it happen again.(Unless, of course, you think its the first step of something else. If Omega shows up to give you a ride, for the love of god, take it... but don't overwrite the save file if you can avoid it.) If you need to make multiple saves to make it easier to get to a timeframe/weather or what have you, do so, but KEEP YOUR FIRST SAVE so we can have a starting point of reference.

When something strange is recorded, it's time to test - When you have something odd happen and you can replicate it, make people aware. Those people can now use your save/weather/time/location/actions information to try to replicate the same thing and get more proof of your discovery/oddity. This will help verify anything found and make it easy to find the specific triggers.

The first area in question will be the Hippy Camp - Please focus all attention there for testing. Feel free to take multiple runs at it using whatever methods you please, but keep all data from the first save and any save you make afterwards from the conditions if something odd should occur for possible replication.

For those on PC - Make sure that mods are disabled, the effects of trainers are nullified (aka, set all trainer settings to default and start a new save BEFORE starting your save for testing. In my experience, the mods can load settings exactly as you had them before) and be aware that mods for changing time/day/weather need to be done OUTSIDE of the area first, and then entering the area when all conditions are stable (time is moving forward, weather is NOT locked - Set the variables, but let the game change them naturally as you enter the testing area so the game can still change something - Testing the Altruists camp myself showed that locking the weather and time didn't allow the game to set those variables the way it wanted)

This also goes for people using cheats on console - Some things change instantly, like the Bigfoot Peyotes will appear if you are near them and change time/weather, but we have no idea what types of triggers other things might need - Its safer to control the variables OUTSIDE of the testing area and enter it fresh.

Hopefully this kind of focused and logged testing will lead to a new lead or a discovery.

We will be doing this for several areas/concepts in the future, so if this particular area isn't your cup of tea, simply wait until an area is posted that you want to test.

And remember "The difference between screwing around and science hunting is writing it down" Me, inspired by Adam Savage.
